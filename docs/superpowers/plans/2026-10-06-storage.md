# Speicherverwaltung Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Sichtbarer Speicherverbrauch, ehrliche Prognosen und geführte Erweiterung für Anker selbst.

**Architecture:** Linux-Erkennung und Prognosen in internal/storage; Messreihen im bestehenden Katalog; eng begrenzte Dateisystemerweiterung im root-Hilfsdienst. Web und CLI zeigen denselben Zustand.

**Tech Stack:** Go, Linux util-linux/e2fsprogs/xfsprogs, SQLite, React, Playwright.

**Spec:** docs/superpowers/specs/2026-10-06-storage-design.md

## Global Constraints

- Nur Anker-Maschine und eigene Laufwerke; keine Proxmox-Gastverwaltung.
- Keine Dummywerte in Produktion, keine Formatierung, keine Verkleinerung.
- Messung stündlich, Aufbewahrung 90 Tage, Prognose 14 Tage, mindestens 24 Messungen und drei Tage.
- Administrative API, root-Auswahl ausschließlich /, /srv/anker und reale Backup-Mounts darunter; Web liefert keine Gerätepfade/Befehle.

## Review Focus

- Bindmount/Containerquoten dürfen keine falsche Summierung erzeugen.
- Wechsel/Vergrößerung und veraltete Messungen dürfen keine alte Prognose behalten.
- Ein zwischen Planung und Ausführung gewechseltes Gerät darf nicht verändert werden.
- Unterbrochene/fehlgeschlagene Erweiterung darf nach Neustart keinen falschen Erfolg zeigen.
- Browserfehler/Demo/fehlende Werkzeuge müssen verständlich angezeigt werden.
